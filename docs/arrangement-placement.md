# 短いフレーズの配置: 主旋律の頂点と休みを取り合わない

アレンジの質を主旋律と同じ水準へ上げる施策の1つ目(`docs/codex-brief-arrangement-quality.md` の7章で Codex と合意した「配置・役割の競合を減らす」)。音高は直さず、置く場所だけを直す。

## わかったこと(開発用の条件、非盲検)

短いフレーズ・イントロ・対旋律・装飾の1案目を同じセクションに重ねて、配置の取り合いを数えた(`observeStack`、記録専用)。

- 2つ以上のレイヤーが同じ休みに入る(応答の位置の取り合い): Aメロ 15/74、サビ 23/73
- 8割以上埋まる休み: Aメロ 35/74、サビ 46/73
- 主旋律の頂点(最高音)で始まる音: Aメロ 16、サビ 21(頂点はそれぞれ 26・38)

レイヤーごとに分けると、頂点へ入っていたのは短いフレーズだった(Aメロ 14、サビ 16)。対旋律・装飾は 0 だった。短いフレーズ1つだけで埋める休みも、Aメロ 23、サビ 34 と他のレイヤー(2〜8)より多かった。

この条件(固定した進行・1案目・4レイヤーを同時に採用)では、短いフレーズが頂点への入りと休みの占有に大きく寄与している。ただし、これを「取り合いの主な原因」と一般化はしない。「2つ以上が入る休み」は、同じ休みの中で2レイヤーが始まるだけで増え、異なる位置で意図して受け答えしている場合も含む。役割の競合や聴いたときの悪さの証明ではない。また、下の選抜では他のレイヤーを空にして余白を評価している。今回の変更は「主旋律との配置」の改善に限って読む。

対旋律・装飾は、すでに主旋律の頂点(`protectedMoments`)と余白の評価(`assessReactiveNegativeSpaceFit`)を使っている。短いフレーズは、主旋律との音域・発音の重なりだけを点数にしていて、頂点と休みの埋まり方を見ていなかった。

## 変更

短いフレーズ(`generatePhrases.ts`)に、既存の評価を使う2つの対応を入れた。新しい物差しは作っていない。

1. **選抜**: 候補を選ぶとき、次の2つを差し引く(作り直しにも同じ補正をかける)
   - 対旋律・装飾と同じ余白の評価(`assessReactiveNegativeSpaceFit`)の不足(1点あたり 0.15)。候補が鳴る区間(候補の長さ)の中だけで評価し、候補の後ろの主旋律の休みは数えない
   - 主旋律の頂点(`protectedMoments` の highest-note)が鳴っている間に始まる音の数(1音あたり 6)
2. **削る**: 主旋律の頂点が鳴っている間に始まる音を削る。入り(最初の音)と終止(最後の音)は残し、残りが4音未満(短いフレーズとして点数を付けない音数)になる場合は削らない。品質の点数は削った後の音で付ける

頂点の判定は、観測(`observeStack`)と同じ基準で行う。頂点の区間(演奏処理後の主旋律から求める)と候補の音の開始を、どちらも16分音符の格子に丸めて比べる。丸めるのは判定だけで、音のタイミングは変えない。以前は候補の開始を丸めずに比べていたので、生の開始が 3.89 拍の音を処理側は頂点の前、観測側は4拍目(頂点の中)と扱う食い違いがあった(Codex の指摘)。テストでは、ストアと同じ演奏処理を通した音も観測と同じ格子で数える。

`placement`(`current`・`select`・`trim`・`both`)で切り替えられる。**既定は従来どおりの `current`**。下の確認用の条件は4案の比較と `both` の選択に使ったので、独立した最終確認ではない。聴いて方向を判断するまで、`both` は既定にしない(下の「聴いて判断するなら」)。

比べなかった案:

- **生成を見送る**: 短いフレーズは作曲者がボタンで頼んだときに作るので、空の結果を返す経路は作らない。ただし「追加なし」は、聴き比べの比較対象にはできる
- **既存のモチーフを短く再提示する**: 既存の素材を使い回す設計案で、イントロを写す経路を新しく作る必要はない。別の小さな施策として残す

読み取り(確認用の条件):

- 両方(both)で、短いフレーズが主旋律の頂点で始まる音は、Aメロ 9→0、サビ 10→2 に減った(残る2音が入り・終止の音かどうかは数えていない)。4レイヤーで頂点に入る数も 10→1、13→5 に減った
- 短いフレーズだけで8割以上埋めた休みは 43→26、29→12 に減った。4レイヤーで8割以上埋まる休みも 50→35、35→25 に減った。2つ以上が入る休みは 16→12、13→13
- 品質の点数は 75.7→76.2 で、ほぼ変わらない。点数と頂点への入りの減少だけでは、聴いた方向の判断はできない
- 削る(trim)だけでは、休みの埋まり方はほとんど変わらない。選抜(select)だけでは、音数が 14.2〜14.5 まで減る
- 開発用の条件でも、同じ向きだった

副作用として残すこと:

- 1案の音数は Aメロ 21.0→20.2、サビ 21.2→20.4。音数を減らすことは目標ではない
- サビの主旋律との平行5度・8度は 9/88→11/80(同じ向きの組の数も変わる)。一律の平行の禁止や、新しい点数合わせでは追い込まない
- 聴いての確認はしていない。数の改善を、聴いた品質の改善とは扱わない

その他:

- 生成時間は、確認用の条件の短いフレーズ(24回の合計)で 321→388ミリ秒(1回あたり約3ミリ秒増)
- 候補の不足(候補が返らない)は、どの案でも 0
- イントロの中の装飾語彙の経路・装飾の旧来の独立した経路は、この変更の対象外
- 既存の Technique の実験の有効・無効や重みは、この結果では変えない

## 聴いて判断するなら(最大3組)

`both` を既定にするかどうかは、方向を変える判断なので、聴いて決める。次の3組に絞る(Codex の提案)。

- 応答が要る主旋律の休みの例、主旋律の頂点の例、くり返す背景のフレーズの例を、各1つ
- 同じ主旋律・コード・音色・音量で、`current` と `both` を盲検で比べる。必要なら1組を「追加なし」との比較にする
- 聴くこと: 短いフレーズの役割が残るか、主旋律が聴きやすいか、削った所が不自然な穴にならないか
- 比べる前に、音符の数値や答えは見せない
