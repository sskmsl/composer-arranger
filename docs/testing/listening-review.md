# 代表曲の聴感・Logic確認

この一式は比較検証用の固定入力です。製品のプリセットや、特定の実在曲を再現する機能には追加していません。

## 再生成

`npm run qa:listening -- --out /private/tmp/arranger-listening-review --compare docs/testing/listening-baseline.json`

4/4の短調・長調、3/4、6/8、長い構成の5条件をseed19/41で作ります。各条件に全区間の伴奏・採用追加層MIDI（`-full.mid`）、採用主旋律だけのMIDI（`-lead.mid`）、アプリで開ける曲JSONがあります。`manifest.json`に拍子、テンポ、小節、区間、音数、音域、MIDIハッシュを記録します。書出し後のMIDIを実際に再解析し、伴奏と主旋律の両方に音符があることを確認します。`-full.mid`はアプリのアレンジ書出しと同じ内容で、主旋律を含みません。全パートを聴くには2つのMIDIを同じ曲頭へ読み込みます。各トラックにLogicの音源を割り当てる形式で、GM音源のチャンネル容量を測る資料ではありません。

ハッシュが変わった場合は、変更前と変更後の両方を残して比較してください。新しい基準への更新は、変更の意図と確認結果を記録してから行います。この数値基準だけで聴感品質が保証されるものではありません。

## Logicで同じ条件を作る

1. 空のプロジェクトへ`-full.mid`を読み込み、MIDIのテンポ・拍子を使用します。区間マーカーがmanifestの区間・小節位置と合うか確認します。
2. 各トラックへ音源を割り当てます。比較前後は同じ音源・設定・音量にそろえ、比較のために片方だけミックスを調整しないでください。
3. `-lead.mid`を別トラックの1小節目へ読み込みます。主旋律をソロで確認してから、伴奏と一緒に再生します。主旋律MIDIを重複して読み込まないでください。
4. 全曲へ戻し、Aメロ→サビ→大サビ、区間境界、イントロとアウトロを確認します。長い曲は後半の音数や低音の重なりも確認します。
5. 3/4と6/8は、拍・小節線とアクセントが合うかを別々に確認します。

## 記録欄

下表を条件ごとにコピーし、変更前と変更後を同じ再生音量で比較します。未確認は空欄のまま残します。

| 項目 | 記録 |
| --- | --- |
| case key / 比較するcommit | |
| Logic・OS・使用音源 | |
| MIDIのテンポ・拍子・小節位置 | |
| 主旋律の聴き取りやすさ（埋もれる区間） | |
| 過密・低音の濁り（区間と小節） | |
| サビ・大サビの差、盛り上がり | |
| 区間境界の休符・つながり | |
| リフの入り方と主旋律との重なり | |
| 変更前より良い／同等／悪い・理由 | |

自動検証で確認できるのは、再現性と書出しデータの整合です。Logic実機・使用音源での聴感確認は、人がこの記録を埋めて初めて確認済みとします。
