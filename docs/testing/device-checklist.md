# 実機確認チェックリスト(Issue #231)

自動テストでは確かめられない、実際の端末・アカウント・Logic Pro での確認です。上から順に、できるものだけ行ってください。結果は表の「結果」欄へ ○ / × / メモ で書きます。できない項目は空欄のままにします。

- 手順の詳細は [reliability-checks.md](reliability-checks.md) と [listening-review.md](listening-review.md) にあります。
- ブラウザの保存データやトークンを手で書き換えて「確認済み」にしないでください。
- 確認には、本番の大事な曲ではなく、**複製した検証用の曲**を使ってください。

## 準備(5分)

1. 公開版を開き、強制再読み込みをします(Safari は `Option` を押しながら再読み込み)。
2. 画面を開いたまま新しい版が公開されたとき、再読み込みを案内する帯が出ることがあります。出たら再読み込みしてください。
3. 検証用の曲を1つ複製します。名前は「検証用」にします。

## A. Mac の Safari(約10分)

| # | 操作 | 合格の目安 | 結果 |
|---|---|---|---|
| A1 | ログインして、検証用の曲の名前を変えて再読み込み | 変えた名前と音符が残っている | |
| A2 | 「アレンジ・書出し」で「曲全体MIDI」を保存 | ファイルが保存され、Logic に読み込める | |
| A3 | 「Active Melody」の書出しを保存 | 同上。画面に「重なっている○音を省く」と出る曲では、その旨が見える | |
| A4 | AI相談に、質問の形で話しかける(例: 「サビが弱い理由は?」) | 3案を出さずに、会話で答える | |

## B. iPhone の Safari(約15分)

| # | 操作 | 合格の目安 | 結果 |
|---|---|---|---|
| B1 | 再生ボタンをタップ | タップした直後に音が鳴り、停止できる | |

## C. アカウントと別端末(約10分)

| # | 操作 | 合格の目安 | 結果 |

## D. Logic Pro での聴き比べ(約30分)

あらかじめ用意した固定の曲(伴奏と主旋律の MIDI、5条件 × 2種)を使います。

1. `npm run qa:listening -- --out ~/Desktop/arranger-listening-review` で作ります(約20秒)。作り方に迷ったら、私に頼んでください。
2. 空の Logic プロジェクトへ `*-full.mid`(伴奏)を読み込み、各トラックへ音源を割り当てます。
3. `*-lead.mid`(主旋律)を別トラックの1小節目に読み込みます。

| # | 確認すること | 見る場所 | 結果 |
|---|---|---|---|
| D1 | 主旋律が伴奏に埋もれていないか | サビ、大サビ | |
| D2 | 低音が濁っていないか、音が重なりすぎていないか | 長い曲の後半 | |
| D3 | 区間の変わり目で、休符とつながりが自然か | Aメロ→サビ、サビ→大サビ | |
| D4 | ギターのリフの入り方と、主旋律との重なり(Issue #207) | 2回目のサビ | |
| D5 | リフを休ませた区間が、画面の理由の説明と合っているか(Issue #218) | 「リフを休ませた理由」の表示がある曲 | |
| D6 | 3/4 と 6/8 で、拍と小節線が合っているか | `minor-34-*`、`major-68-*` | |
