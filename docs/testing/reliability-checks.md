# 保存・認証・Safari系の確認

## 自動検証

```
npm ci
npx playwright install --with-deps chromium webkit
npm test -- --maxWorkers=2
npm run qa:listening -- --out test-results/listening --compare docs/testing/listening-baseline.json
npm run test:e2e
```

ChromiumとWebKitで、PC幅1280pxとモバイル幅390pxを確認します。WebKitモバイルはタッチ・モバイル動作を模擬します。実際のSafariアプリやiPhoneのOS保存画面を操作した結果とは分けて扱います。

ブラウザはエンジンごとに実行し、既存の1件60秒・全体300秒・再試行0を維持します。結果と失敗証拠は`test-results/chromium`、`test-results/webkit`、`playwright-report`へ分けて保存します。CIと手動Pagesは両方のエンジンとMIDI基準比較を通過してから公開します。

### 認証を含む検証範囲

`e2e/authRecovery.spec.ts`は実際のAuthGate・ログインフォーム・App・IndexedDBを使います。SupabaseのSDK/サーバー境界だけを`e2e/authFixture.ts`に置き換え、外部通信を遮断します。この入口・fixtureは`dist-e2e`専用で、公開distへ含めません。検証用のメールアドレスとパスワードは架空で、実認証情報は渡しません。

- 未送信分の再読込後の復旧、回線復帰での再送、同じ保存時刻の新旧編集の応答順序。
- 別アカウントへの未送信データの混入防止と、元の所有者に戻った場合の復旧。
- 未送信曲を削除した後に、保存の再送で復活させず削除通知を送ること。別端末で削除された曲も、新しいオフライン編集で復活させないこと（再読込・回線復帰）。
- 編集中でない未保存曲のJSON退避。編集中の曲を置き換えず、既存の曲JSON形式を維持すること。
- 遅れた初期セッション、旧アカウントの同期終了、素早い同一アカウントへの再ログイン。
- 初期セッション確認の失敗から、ログインまたは再確認へ進めること。
- DB v1からv2への移行と、旧タブによる移行の停止からの復旧。既存曲を削除しないこと。

### 読込失敗からの復旧

WebKitの固定版で、modulepreload失敗がreload後も残るケースを再現しました。テストの遮断や復旧後の表示条件を保ったまま、遅延importのJS先読みを除外しています。HTML入口の先読みとCSS、画面の遅延読込は維持します。[WebKitの該当報告](https://bugs.webkit.org/show_bug.cgi?id=270357)、[Viteの設定仕様](https://vite.dev/config/build-options.html#build-modulepreload)を参照。

## あとで行う実機確認

以下は自動検証とは別の、未確認項目を埋めるための手順です。確認には複製した検証用の曲を使い、環境・結果・失敗した操作を記録します。

| 環境・操作 | 合格の目安 | 結果 |
| --- | --- | --- |
| macOS Safariでログインして曲名を変更、再読込 | 最後の曲名と音符が残る | 未確認 |
| iPhone Safariで再生ボタンをタップ | ユーザー操作から音が鳴り、停止できる | 未確認 |
| iPhoneでJSONとMIDIを保存 | 実際の保存先から取得でき、JSONを再び開ける | 未確認 |
| 別アプリへ切り替えてSafariへ戻る | 編集内容が残り、必要な再生操作で再開できる | 未確認 |
| 回線を切った状態で編集し、復帰する | 端末保存とクラウド未送信を区別して表示し、復帰後に再送する | 未確認 |
| ほかのタブで開いた状態から更新する | 案内が出た場合、旧タブを閉じて再試行すると既存曲が戻る | 未確認 |
| 検証用アカウント間の切替 | 別所有者の曲を表示・送信せず、元のアカウントで続けられる | 未確認 |

アカウント切替操作が利用環境にない場合は、その項目を未確認のまま残します。ブラウザストレージやトークンを手動で書き換えて確認済みとはしません。

音楽面は[代表曲の聴感・Logic確認](listening-review.md)のMIDI一式と記録欄を使います。音源・再生音量・Logicの設定を比較前後でそろえてください。
