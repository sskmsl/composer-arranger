# 旋律の質をさらに高めるための相談(Codex への依頼書)

Composer Arranger の主旋律生成を、人が「良い」「口ずさめる」と感じる方向へさらに高めたい。
これまでの経緯と測定結果、制約、Claude 側の施策案をまとめる。**独立した視点での施策案と、Claude 案への反論・見落としの指摘**をお願いしたい。

## 1. 目的と、利用者が大事にしていること

- 目的は特定の曲をまねることではなく、「良いメロディ」を生成できるようにすること。
- 利用者(作曲家)が良いと感じた参考曲(AI 生成のポップス)の要点は「全体を通して口ずさめること」。音域の広さは問わない。コードに合うことも大切。
- 利用者は、最終的には自分の耳で判断する。数値は補助。

## 2. いまの生成の仕組み(要点)

- `src/melody-engine/generateFromChords.ts`: 作り方(profile)ごとに候補を多めに作り、品質・多様性の条件で3案を選ぶ(`candidateSelection.ts`)。
- Hook-first: 最初に短い核(`hookFirst.ts` の `selectCoreMotif`)を選び、フレーズの役割(提示・応答・発展・回帰・上昇・頂点、`hookDevelopment.ts` の `hookPhraseRole`)で育てる。
- 仕上げ: `melodicCraft.ts`(作り方ごとの段階的な推敲)→ `restoreHookHeads`(核の頭を戻す)→ `repeatOverReturningHarmony`(同じ和音の並びで核をくり返す)→ 頂点の時機・息継ぎ・和声の整合。
- 物差し: 核の歌いやすさ・覚えやすさ(`judgeCoreMotif`)、感情の弧(`emotionalArc.ts`)、動機の育ち方(`motifRecognition.ts`)、古典らしさ(`classicalLikeness.ts`)、口ずさみやすさ(`hummability.ts`)、予想しやすさ(`expectation.ts`)。
- 変更前後の比較テスト: `developmentPrinciples.comparison.test.ts`(同じコード・seed で動機の育ち方・頂点・息継ぎ・古典らしさを測る)。

## 3. これまでに分かったこと(数値)

詳しくは `docs/memorable-melody-research.md` と `docs/composer-principles.md`。

- 核の歌いやすさは以前、音域が10半音を超えると減点していた。利用者の録音の冒頭(5度を連ねてオクターブを超える)を「最も歌いにくい」と判定していたので、音程ごとの歌いやすさで測るように直した(録音の2小節ごとの平均 0.80 → 0.93)。
- 旋律全体の口ずさみやすさ(音程の歌いやすさ・息継ぎ・速さ)は、全ての作り方で 0.87〜0.98 と差がつかず、選抜には使っていない。
- 予想しやすさ(IDyOM を簡単にしたもの、パブリックドメインの歌502曲 OpenEWLD の音程の出やすさで学習)で測ると、生成した旋律は歌より予想しにくい側に偏っていた。
  - 歌: 平均情報量 2.94 ビット/音(上位25%の境 3.24)。標準: 3.47、上位25%を超える割合 52%(歌では25%)。
  - 差の一部は音の動きそのもの(約0.3ビット)、残りは曲の中のくり返し(2小節がそのまま戻る割合: 歌 6%、生成 0〜1%)。
- 対策1: 選抜で、予想しやすさが歌の25〜75パーセンタイルにあるものを優先 → 3.47 → 約3.37。
- 対策2: 同じ和音の並びが戻る所で核をそのままくり返す → 2小節がそのまま戻る割合 6%、情報量 3.31。動機の育ち方・頂点までの段階的な成長・息継ぎも改善。古典らしさは 97.7 → 96.3 と少し下がった。
- 効果がなく採用しなかった: 長い音を主和音の音(1・3・5度)へ寄せる仕上げ。

## 4. 制約

- 既存の曲の旋律・音型を保存・再現しない。学習や較正に使うのは、パブリックドメイン・CC0 など権利が明確なデータの統計だけ(OpenEWLD、OpenScore Lieder)。非商用限定のデータ(Essen 民謡集、DCML の一部)は新しい物差しに使わない。
- 既存の設計(Hook-first、感情の弧、Boutonnat 的な「足すより削る」)を壊さない。
- 変更は、同じコード・seed での前後比較で効果を示す。効果が測れない変更は入れない。
- ブラウザで動く TypeScript。生成は数秒以内。

## 5. Claude の施策案(優先順)

1. **聴いた評価を集める仕組み**(最優先):候補ごとに「良い/いまいち」と理由のタグ(口ずさめる・単調・跳びすぎ・刺さる など)を付けられるようにし、候補の特徴量と一緒に記録する。
   - 2案を並べて片方を選ぶ比較(Bradley–Terry)で、作り方・重みを利用者の耳に合わせる。
   - 研究の物差しは代理指標にすぎない。人の評価だけが正解になる。
2. **3案を「予想しやすさ」の軸で意図的に散らす**:「定番寄り」「中くらい」「冒険寄り」の3案にして、名前でも分かるようにする。
   - 根拠: 好まれる予想しやすさには個人差がある(Gold et al. 2019)。※Codex の指摘により訂正: 好みの鋭さとの関係が見られたのは Study 1 の知覚能力(Gold-MSI)で、経験年数では有意でなかった。
3. **驚きの置き場所**:いちばん予想外の音が、核が1〜2回聴こえた後(3小節目以降)の、構造上の要所(頂点・倚音)に来ているかを測り、選抜と仕上げに使う(Sloboda 1991、Gold et al. 2019)。
4. **リズムの予想しやすさとシンコペーション**:いまの予想しやすさの物差しは音高だけ。発音間隔の予想しやすさを足し、シンコペーションは中くらいが好まれる(Witek et al. 2014)ことを選抜に入れる。
5. **現代のポップスの物差し**:OpenEWLD は1900〜1930年代の曲が中心。現代のポップスはシンコペーション・同音・Aメロの狭い音域・サビで広がる形が多いとされる。権利の明確な現代曲の統計(論文に載っている数値など)で物差しを補う。
6. **Aメロは和音から少し自由に、サビは和音と一体に**(Temperley 2007 の loose verse / tight chorus)。
7. **ポップス系の作り方では、跳躍の後に戻す仕上げを弱める**(von Hippel & Huron 2000。戻りの傾向は古典で強く、民謡・ロックで弱い。参考曲は 0.18)。
8. **予想しやすさの物差しを、生成そのものに使う**:選抜だけでなく、次の音を選ぶ段階でコーパスの出やすさを使う(学習した「よくある形」を持つ点が、AI 生成曲が口ずさみやすい理由の一つではないか、という仮説)。

## 6. Codex にお願いしたいこと

1. 上の案への反論と、見落としている点(特に「物差しが人の好みを本当に測れているか」)。
2. Claude 案にない、独立した施策案(研究・作曲の教本・実務の知見から。出典つき)。
3. 優先順位の付け直しと、それぞれの効果を前後比較でどう測るか。
4. 実装する場合の危険(生成時間、既存テストの閾値、Hook-first との衝突)。
