# 1音だけ飛び出す音と、推敲(古典らしさへ寄せる最終段)

## 出発点

作曲者の感想(2026-09-27)は、以前の生成についてのもの。「メロディアスではない」「たまに音が一音だけズレる」「同じ音程をぐるぐる回しているだけ」だったが、Codex とのやりとりの前(#165 まで)の改修で改善されてきた。今も残っているという報告ではない。

そこで、これらが今の生成にどれだけ残っているかを数えた(非盲検)。

## 結論

- この PR で入れる変更は、推敲の動く幅の上限を、コメントに書いてあった設計(推敲前の音から4半音まで)に合わせる修正だけ。
- 「1音だけ飛び出す音」を新しく作らないという禁止条件も試した。しかし、新しい音楽的な制約であり聴いての確認がないので、採用しない(下の「試して採用しなかった制約」)。
- 試聴は頼まない。今も残るという報告ではないので、数が減ることを理由に、解決済みの問題を再び課題にしない。

## 数えたこと

条件(開発用): 8進行(C・G・F・D・Am・Em・Eb・Dm)× Aメロ・サビ × 曲の雰囲気2つ(original-custom・dark-romantic)× seed 11・22・33、8小節、標準の作り方、公開ルール(アプリの既定と同じ経路)。1版につき 288 旋律。

### #165(2c4905a)と #182(d22294e)

全体としてはっきり悪くなった所は見つからなかった。変わったのはサビ。

- サビの古典らしさの平均は 91.4 → 88.1(Aメロは 95.4 → 96.3)
- サビで、同じ3音程の並びがくり返される割合は 0.041 → 0.086。#168 以降の「コードが戻る所で核をくり返す」の効果で、意図した変化
- 実在曲(下の OpenEWLD)の8小節の窓は 0.166。「同じ音程をぐるぐる」は、音程の並びのくり返しの量では説明できない

### 調の外でコードにもない音

実在曲より少ない(実在曲 2.53、#165 1.80、#182 1.49 / 100音)。1拍以上、拍の頭で、コードの音と半音でぶつかる音も同じ程度。

### 1音だけ飛び出す音(記録用の形の候補)

定義(`isIsolatedLeap`、`melodyCraftMetrics.ts`、記録専用): 1拍以下の音が、前の音からも次の音からも同じ向きに7半音以上離れている。前後どちらかに1.5拍より長い休みがあれば、フレーズの切れ目として数えない(`leapRecovery` と同じ切れ目)。

これは形の候補を数えるためのもので、悪い音の判定ではない。7半音の往復は、和音の分散や意図したフックでも成り立つ。1拍・7半音・1.5拍の境界も、聴いて決めた正解ではない。

| | 実在曲の目安 | #165 | #182 |
|---|---|---|---|
| Aメロ | 0.62 / 100音(0.40〜0.91) | 0.91 | 0.96 |
| サビ | (同上) | 0.54 | 0.46 |

実在曲の目安は OpenEWLD(https://github.com/00sapo/OpenEWLD 、パブリックドメインの歌のリードシート502曲)で数えた。数え方は `tools/melody-reference/ewld_isolated_leaps.py` にある。

- タイはつなぎ、四分音符=1拍で32拍の窓に分けた
- 窓の端をまたぐ3音は数えず、休みの切れ目も生成側と同じ規則で除いた
- 500曲・1661窓。窓は同じ曲から複数取るので独立ではない。そのため曲を単位に作り直して、95%の幅を付けた
- OpenEWLD にはAメロ・サビの区別がなく、Aメロ同士を照合した基準ではない。差は参考値で、多すぎることや欠陥の証明ではない

段階の記録(`stageTrace`)で、#182 の最終の音で飛び出している 54 か所について、その3音の形が最後にできた段階を数えた。

- 推敲(`final:refineTowardClassical`)32、サビの持ち上げ(`craft:lift`)12、組み立て 4、ほか 6
- 推敲の 32 か所のうち 9 か所は、何周かして推敲前の音から4半音より動いた音でできていた。コメントには「1音あたり上下4半音まで」とあるが、実装は1周ごとに4半音まで動けたので、周を重ねると4半音を超えていた

推敲でこの形ができた理由は、切り分けていない。推敲は複数の物差しを合わせた分布の高さを上げており、そのどれがこの形を選ばせたかはわからない。なお、物差しの「跳躍の後の戻り」(`leapRecovery`)は逆向きに3半音以内で戻ることを求めるので、両側7半音以上の往復は戻りとして加点されない。例えば半拍の [72, 64, 72] は、飛び出す音だが `leapRecovery` は 0。この観察を理由に物差しは変えない。

## 変更

推敲(`refineTowardClassical`)で、何周しても推敲前の音から4半音より動かさない。コメントに書いてあった設計に実装を合わせる修正で、閾値と下限は変えていない。

開発用の条件(6進行 A・Bb・Cm・E・F#m・Ab × seed 71・83・97 × Aメロ・サビ × 8・16小節 × 雰囲気2つ、432 旋律、`isolatedLeap.comparison.test.ts`)での記録は次のとおり。この条件も、結果を見て修正を重ねた後なので、開発用の条件として扱う。

| | 1音だけ飛び出す音(/100音) 前 → 後 | 古典らしさの平均 前 → 後 |
|---|---|---|
| Aメロ 8小節 | 0.38 → 0.31 | 92.91 → 93.47 |
| Aメロ 16小節 | 0.66 → 0.50 | 94.54 → 95.61 |
| サビ 8小節 | 0.78 → 0.82 | 89.29 → 89.10 |
| サビ 16小節 | 0.66 → 0.59 | 92.52 → 93.24 |

古典らしさは推敲が上げようとしている値そのものなので、その上下は独立した品質の確認ではない。

核の維持(`coreRarityProtection.comparison.test.ts` の既定側、最終の3案 288)は、変更の前後で次のとおり。ほぼ変わらない。

- 移調を許した形が一致する割合: 0.118 → 0.122
- 核の範囲でオクターブ動いた音: 32 → 32

既存のテスト(下限を含む)はすべて通る。

再現: 変更の前後それぞれで、次の2つを実行する。変更前のコードには `isIsolatedLeap` がないので、同じ定義を足して動かす。

- `ISOLATED_LEAP_OUT=<出力先>.json npx vitest run src/melody-engine/isolatedLeap.comparison.test.ts`

## 試して採用しなかった制約

推敲の置き換えで、置き換えた音とその前後に、新しく「1音だけ飛び出す音」の位置ができるなら見送る制約も試した。開発用の条件では、上限と合わせて 0.24 / 0.24 / 0.36 / 0.32(上の表と同じ4区分)まで減った。

採用しない理由は次の2つ。

- 新しい音楽的な制約なので、聴いての確認がない
- この形は意図したフックや和音の分散でも成り立つ

後日採用を判断するために聴くなら、比べるのは「上限のみ」と「上限+制約」。同じ核・同じ候補で、先に決めた規則により次の各1組を選ぶ。

- (a) 新しい短い往復が抑えられた代表例
- (b) 元の跳躍にフックとしての役割がありそうな例
- (c) 終止や頂点の近くで変更が波及した例

改善量が最大の例だけは選ばない。「同じ・違いがわからない」も答えられるようにし、答えは先に見せない。

## 残したこと

- サビの持ち上げ(`craft:lift`)でできる「1音だけ飛び出す音」は、この変更の対象外
- 「メロディアスではない」「同じ音程をぐるぐる」は、今回の記録(音程の並びのくり返し・音の往復・狭い音域に留まる長さ)では実在曲との差が見つからなかった
