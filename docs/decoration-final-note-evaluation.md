# 装飾の評価を、実際に返す音にかける

#184 で Codex が挙げた「実装の注意」の1つ。音楽の方向を変える施策ではなく、評価の正しさを直す修正。

## 問題

装飾(`decorationGenerator.ts` の `buildCandidate`)は、生成した音に和声の補正(`enforceHarmonicIntegrity`)をかけて返す。一方で、次の評価は補正前の音(`rawNotes`)にかけていた。

- 和声の適合・つなぎの質・音楽性
- 主旋律との関係・衝突(`evaluateReactiveLayerQuality`)
- 余白の評価・採用済みの伴奏との関係

そのため、選抜のしきい値や画面に出る衝突の数が、実際に鳴る音と食い違うことがあった。

既存のテスト(主旋律がない Outro の終止の身振り)は、この食い違いのおかげで通っていた。テストは `parseChordInputText` に1小節8拍を渡していて、32拍の区間の最後のコードは Am でなく G になっていた。補正前の音は主音 A へ解決して「つなぎの質 100」と評価されていたが、実際に返していたのは、補正で B へ動かされた音だった。テストの前提を、コードの文字列どおりの1小節4拍に直した。同じファイルのもう1つのテストも、同じ読み違いを直した。いずれも期待値は変えていない。

## 変更

評価を、和声の補正の後の、実際に返す音にかける。しきい値と重みは変えていない。

回帰テストでは、返す候補の衝突と余白の評価が、返す音から計算し直した値と一致することを確かめる。このテストは、修正前のコードでは落ちる。

## 前後の比較(記録専用、非盲検)

`arrangementQuality.baseline.test.ts`(短いフレーズの配置は既定の `current`)で数えた。変わったのは装飾だけで、他のパートは同じ。

候補の数(12回の合計):

| 条件 | 単独 Aメロ | 単独 サビ | 組み合わせ Aメロ | 組み合わせ サビ |
|---|---|---|---|---|
| 確認用 | 109 → 111 | 102 → 105 | 113 → 118 | 94 → 105 |
| 開発用 | 92 → 98 | 116 → 116 | 94 → 98 | 115 → 116 |

候補が返らなかった回数は変わらない(確認用 0、開発用 Aメロ 1)。

- 1案の音数は少し増えた(全候補で +0.1〜0.2音)
- 主旋律との短2度はどの条件でも 0 のまま。採用済みのレイヤーとの短2度は、確認用の組み合わせのサビで 0 → 0.007(134音中1音)
- 平行5度・8度と、拍の頭がコードの音である割合は、条件によって増えたり減ったりした。判定対象の数が少ないので、向きは言えない

これは評価と実際の音を一致させる修正で、聴いた品質の改善とは扱わない。
