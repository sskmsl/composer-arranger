# アレンジに「感情を動かす仕組み」の軸を加える

アレンジ側の弱点は、旋律に比べて「感情を動かす仕組み」を扱う軸が無いことだった。音色やコードの表面ではなく、
聴き手の中で何が起きるか(機能)を軸にして、語彙・測定・選抜・登録・画面までを揃えた。
旋律側が持つものと同じ4点を、アレンジ側にも持たせることを完了条件にした。

| 旋律側が持つもの | アレンジ側で足したもの |
| --- | --- |
| 参照から取り出した統計（`composerPrinciples.json`、割合と中央値だけ） | `reference/arrangementEmotionPrinciples.json`（参照録音5本の本数と中央値） |
| 感情曲線の構造指標（`docs/emotional-arc-melody-audit.md`） | `arrangementEmotion.ts`（仕組みの得点と総合の代理値 arcScore） |
| 変更前後の比較 | 下の「変更前後」（main と、同じ構成・seed・物差し） |
| テスト | `emotionalMechanism.test.ts`、`arrangementEmotion.test.ts`、`arrangementPatterns.test.ts` |

## 先に挙げた5つの弱点と、その解消

| 弱点 | 解消 |
| --- | --- |
| 意図が自由記述で、機能の語彙が型として無い | `src/core/emotionalMechanism.ts`。仕組み4つ（期待→到来 / 引き算による対比 / 終止の減衰 / 蓄積）と、測る4軸（土台・明るさ・強さ・層の数）、手段6つを型にした。`directive.emotionalMechanisms` で型のある指定ができる。手段を省くと、観察本数を重みに曲とseedから決める |
| 選抜が、意図の達成度を測らない | 指定した仕組みが実音で起きた度合い（0〜1）を、意図の適合に6割混ぜる。方向の名前の対応表は4割に下げた |
| アレンジ全体の感情曲線の代理指標が無い | `measureArrangementEmotion`。録音の曲線と生成物の曲線を、同じ関数で採点する。`quality.metrics.emotionalArcScore` と仕組みごとの得点に出す。品質の点数（score）には入れない |
| 型が「何をするか」のレシピで、「なぜ効くか」が無い | 型を手段（means）に再編し、仕組みの下に複数置いた。仕組みは感情への働きと実音の署名を持つ。画面は仕組みごとに手段を並べる（観察本数などの根拠は画面に出さない。内部の重みとおすすめの判定にだけ使う） |
| 学習パイプラインを通っておらず、根拠が1本 | 参照を1本から5本に増やして解析した。手段をTechnique（TECH-8001〜、Draft）として登録し、対象 `arrangement` と軸 `emotionalMeans` を公開スキーマに足した。Rule Resolver 経由の Auto も実装した（Draftなので既定では何も補わない） |

## 参照5本の解析（信号処理による推定）

方法は `tools/arrangement-reference/`。小節ごとの帯域強度（低域=土台、高域=明るさ、RMS=強さ）、キックと高域の発音数、左右の広がりを求め、
同じ採点関数で採点した。楽器の判別やコードの推定はしていない。録音は約4分で、テンポ85〜120 BPM。

| 仕組み | 観察本数 | 内容（中央値） |
| --- | ---: | --- |
| 期待→到来 | 4/5 | 序盤に低域が基準より約18dB低い状態が約22小節続き、約12dBの上がり幅で戻る。同時に入る層は2 |
| 終止の減衰（画面の名前は「終わりの余韻」） | 5/5 | 最後の4小節で強さが小節ごとに下がる（音のある範囲で約14dB、最小でも約5dB） |
| 蓄積 | 2/5 | 序盤で強さが上がり続ける |
| 引き算による対比 | 1/5 | 途中で低域を約8小節抜いて、約27dBで戻す |

手段ごとの本数は、リズムを進めたまま低域だけ保留する（bass-withheld）が3、ドラムレス（キックと低域をまとめて保留）が1、
到来の直前の1小節の静けさが2、低域とキックを抜く区間が1、フェードが5、層を一つずつ引くのが2。

実測で、前の仮定を2つ直した。
- 前に加えた「ドラムレスのイントロ」は、5本中1本でしか観察されなかった。いちばん多かったのは、キックを鳴らしたまま低域だけを後から入れる形（3本）。
  これを手段 `bass-withheld` として加えた。ドラムレスは残す。
- 私が仮定した「低域を先、キックを最後」の二段の到来と、「高域を引く区間」は、どの録音でも観察されなかった。手段に入れていない。

参照の総合点（arcScore）は 35.9〜85.0、中央値 73.9。5本のうち1本は序盤の保留が無く、総合点が低い。

## 変更前後（main と、同じ構成・seed 1〜8・同じ物差し）

| 構成 | 総合点 前→後 | 終止の減衰 | 品質の点数 | 和声違反・旋律との衝突 |
| --- | --- | --- | --- | --- |
| フル（アウトロ8小節、10区間） | 54.2 → 92.2 | 0.05 → 1.00 | 84.3 → 84.2 | 0 → 0 |
| 中（アウトロ4小節、8区間） | 77.0 → 84.8 | 1.00 → 1.00 | 84.0 → 83.7 | 0 → 0 |
| 序盤が4小節の短い曲 | 40.0 → 40.0 | 変化なし | 変化なし | 0 → 0 |
| アウトロの無い曲 | 42.2 → 42.2 | 変化なし | 変化なし | 0 → 0 |

「中」だけは、感情の曲線を選抜に6%入れた結果、選ばれる候補が変わった（蓄積 0.01 → 0.28、到来 0.77 → 0.88）。
音数が増え（1254 → 1650）、同じ役割の再登場でのコピー率の最大が 0.50 → 0.57 になった（合格の上限は 0.65）。

`emotionalAuto: false` を渡すと、既定の閉じ方も選抜の重みも無効になる。このとき、3構成 × 6seed × 2指示の36パターンで、音が main とバイト単位で一致した。

## 既定で働かせたもの・働かせなかったもの

- 働かせた: 終止の減衰（アウトロで終わる曲）。5/5で観察され、既存の固定テストを1件も壊さなかった。
- 働かせなかった: 序盤の保留→到来。4/5で観察されたが、既定にすると、既存の固定テスト6件（導入の段階化、低音の扱いなど確立済みの動作）が壊れた。
  既存の期待値は変えない方針なので取り下げ、選ぶ入口と、不足を示すおすすめに回した。
- 画面（方向選び）は、いまのアレンジで起きていない仕組みを、測った得点から「この曲に足りない」と示す。観察が3本以上の手段だけを勧める。

## 検証

- 型チェック・ビルド成功。lint は既存の警告1件のみ。
- `npx vitest run --maxWorkers=2`: 1427件成功・7スキップ、失敗0。作業前（main）は1382件。既存の期待値は変更していない。
- 新しいテスト: 語彙（文言の相互の読み違いが無い、観察本数が集計と一致）、採点（保留と到来、引き算と序盤の区別、減衰、蓄積）、
  各手段（実音のMIDIを読み直して測る）、Auto（検証済みRule）、選抜、公開ライブラリ（Draftは何も補わない）、スキーマ。
- テストが見つけた設計のずれを2つ直した: 「低域を保留」の文がドラムレスの検出に当たっていた。総合点の重みが観察本数の順と逆だった。

## 限界

- 録音5本は、同じ制作者の個人の制作物で、独立したGenre Sourceではない。人によるEvidenceの確認もまだない。
  そのため、Techniqueは Draft のまま。人が Validated にしたときに、Auto で手段を選ぶようになる。
- 点数は、仕組みが実音の上で起きているかを調べる代理値で、聴いたときの感動を保証しない（旋律側の構造指標と同じ位置づけ）。
  私は音を聴けない。実際の聴き心地は、方向選びで手段を選んで聴いて確かめる必要がある。
- 点数が飽和する仕組みがある（既存の序盤の保留や、ブレイクダウンでの補助ベースの引き算は、すでに高得点）。
  差が出るのは、終止の減衰、短い序盤、アウトロの無い曲。後二者は、既存の期待値を壊さずに既定へ入れる道がまだ無い。
- フェードアウトは velocity による段階的な下げで、ミックスのフェードほど滑らかではない。
- 左右の広がり（参照では、序盤は広く、到来で狭まる録音があった）は、区間ごとの設定項目が無く、未実装。
