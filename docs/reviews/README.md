# docs/reviews の置き方

変更ごとの検証の記録を置く場所です。増え続けるので、何を置くかの基準を決めます。

## 置くもの

- **報告書(`*.md`)**: 何を変え、何を確かめ、何を確かめていないか。1変更に1つ。
- **テストが読む基準データ**(`*.json`): 例として `melody-consonance-*.json`、`melody-minimum-duration-*.json`。`src/` のテストが参照するので、動かさない・消さない。
- **再現に必要な最小の証拠**: 比較の元になった数値(hash、測定の中央値、条件の一覧)。

## 置かないもの(次の変更から)

- **CI や `npm test` が毎回出す実行ログ**(`*-lint.log`、`*-tsc.log`、`*-build.log`、`*-full-tests.log` など)。結果はPRのCIで見られ、再実行でも得られます。報告書には「成功/失敗と件数」だけ書く。
- **コマンド1つで作り直せる生成物**(試聴用の MIDI など)。作り方(コマンドと入力)を報告書に書く。例: `npm run qa:listening`。
- 数百KBを超える測定の生データ。必要なら、要約と、作り直す手順を残す。

## 命名

- 報告書: `<主題>-<Issue番号>.md`
- 証拠: `<主題>-<Issue番号>-evidence/`(置くのは「置くもの」の3つ目だけ)

## 現状(2026-11 時点)

- `docs/reviews` は約2MB、152ファイル。リポジトリ全体(約7.4MB)の3割弱です。
- そのうち実行ログ(`*.log`)は約0.2MBです。小さいので、**消去はしません**。過去の報告書からのリンクが切れるためです。
- 大きいのは測定の `*.json`(約1.2MB)で、その一部はテストが読みます。
- 新しい基準を適用するのは、これから足す分です。
