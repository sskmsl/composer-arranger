# 保存復旧・認証入口・Safari系検証と確認資料

基線: main `c9a017fde0868358265c27eb0e8616db68863ac7`。今回の対象は、未送信保存、未保存曲の退避、認証入口の統合検証、WebKit、代表MIDIの5項目。

## 変更と保証する範囲

- 端末への曲保存と所有者別のクラウド送信待ちを同じIndexedDB transactionへ記録する。再読込・回線復帰・画面復帰で再送し、一時通信エラーは5秒から最大120秒へ間隔を広げる。端末保存とクラウド送信を別々に表示する。
- 保存版をUUIDで識別し、古い応答が同じ保存時刻の新しい編集を消さない。削除は送信待ちの保存を置き換え、tombstoneの再送で復活を防ぐ。所有者が変わった応答で現在の状態を更新しない。
- 未保存曲一覧から、編集対象を切り替えずに各曲の最新JSONを退避できる。一覧・送信状態は曲JSONへ追加しない。
- AuthGateで遅れた初期セッションや旧同期応答を無効化する。素早い同一所有者への再ログインと初期セッション取得失敗から復帰できる。
- IndexedDB v1→v2は既存曲を残して送信待ちstoreだけを追加する。旧タブが移行を止めた場合は、旧タブを閉じて再試行する案内を表示する。

## レビューで確認した削除優先の回帰

自動レビューの指摘を独立に再現し、別端末の削除時刻より新しいオフライン編集が、再読込・回線復帰でtombstoneを上書きする2条件の失敗を確認した。送信待ちを再生する前に所有者を確認してクラウドmetadataを取得し、削除済みIDへの保存を送らず現在の待機版だけを解消する。metadataを確認できなければ待機版を残す。削除済みとして解消しただけの場合は「送信しました」と表示しない。

修正後は同じE2E2条件が成功。metadata確認失敗・新しい編集より削除を優先・送信したという誤表示の防止をunit3件でも確認した。初期同期の順序だけでなく、account readinessやonline/focusから直接再送する入口にも同じ確認を適用する。
