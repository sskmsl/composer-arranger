# ギターのリフ層：実装と検証（Issue #207）

2026-10-27 JST。基点 main `e8f63e6b8932c126b6662f78a51ba2caeef341a4`、検証対象のソース `0d3b9914cfd1c1ac63dad6a1506aa7208ce2d939`。

既存2層の後に `addGuitarRiffLayer(project, legacyArrangement)` を呼び、単音・パワーコードの反復句を自動で足す。リフ追加、ストラム停止、アルペジオ削減を一つの候補として扱い、候補が成立しなければ従来案をそのまま返す。旧2層の再追加では、既存リフを境界予算の固定側に置き、非対象トラックのオブジェクトと順序を保持する。汎用の保存データ補完からリフを新設しない。

候補の生成・選抜、既存の品質閾値、固定ハッシュ、測定原本は変更していない。リフも既存の和声レビューと聴感測定へ含める。リフ候補には、品質合格・聴感72以上に加え、従来案の品質点・聴感点・衝突数・和声違反数を悪化させない条件を課す。密度・役割の異なる候補を同じ条件で試す。新しい画面・モード・利用者向けプリセットは追加していない。

独立テストの不採用時ハッシュ確認は、上記9条件がすべて採用された実装では条件分岐を通らない。このため別途、不採用になるfixtureを実行した。1・8・13区間の全サビ、固定ID、seed19で、品質点はそれぞれ42.5・72.5・58、すべて品質不合格。実装後もリフ0音で、mainとの全トラック音符ハッシュが一致した。1区間は配置対象なし、8・13区間は低品質案の不採用ケースとして確認した。全入力での棄却動作を保証する測定ではない。

## 生成時間

同一コードのみの固定入力：13区間×16小節、Am、4/4、固定project/section ID、seed19。役割はintro/verse/pre/chorus/verse/pre/chorus/breakdown/bridge/pre/grand-chorus/outro/outro。各区間のコードはAm/F/C/Gを2小節ずつ反復。1回warmup後に5回生成し、mainと実装を順番に、`--maxWorkers=1`、別プロセスで測った。

- main：514.96, 486.39, 458.15, 458.39, 531.43 ms、中央値 **486.39 ms**
- 実装：550.89, 497.50, 537.86, 519.67, 478.17 ms、中央値 **519.67 ms**
- 最終比較の中央値比：**1.0684倍（約6.8%増）**

単一fixture・この実行環境での測定であり、実曲全体の性能保証ではない。全テストの所要時間比較には独立テスト21件の追加も含まれるため、生成時間の比較には使わない。
