# 生成旋律の極短音：原因・修正・検証（2026-10-18）

対象main fbd5bde。作業ブランチ codex/melody-minimum-duration。本番未公開。

## 先に行った切り分け

コード修正前に、指定LCGを使う診断テストを追加して旧出力を保存し、原因と前後の音をチャットで報告した。その後に生成コードを修正した。

- 曲A/B、run=0〜5、Math.randomは1664525×state+1013904223の32bit LCG、初期値5000+run×31。
- UUIDは各runで連番をリセット（00000000-0000-4000-8000-000000000001から）。
- 全9セクションを順に生成し、各3候補を検査。各セクションでは先頭候補を採用。
- 設定standard/balanced/middle/growing。合計324候補、反復72候補。
- この固定条件では総7,893音、極短音37音、極短音を含む反復候補22/72。利用者の7,917音・25/72とは総数/候補内訳が一致しない。差の原因は未確定であり、同じ数字になるようseedやIDを調整していない。極短音37件とMIDI最短4tick、提示された曲A run0/run2の現象は再現した。

**分類：完全同時の重複(a)は0。次の発音直前まで移動されて短縮された(b)が34。コード終端直前まで移動されて短縮された(c)が3。**

発生場所はrepeatedSectionMelody.tsのvaryRepeatedSection。入口を0.25拍遅らせる条件が「次音/コード終端より前」だけで、移動後に残る音価を確保していなかった。演奏済み土台の開始位置に微小な揺らぎがあるため、残りが0.002〜0.015拍になる。その後、コード終端と次の開始位置で切り、Math.max(0.01, …)で0.01拍となる。入力の土台に0.1拍未満はなかった。繰り返し候補はPerformanceを再適用しない経路なので、performanceExecutionやGateが直接0.01拍を作ったわけではない。fbd5bdeの密な音価が、この既存の変奏の境界条件を踏みやすくした。

## 修正

1. 変奏の入口移動より先に最低0.1拍を予約。元から移動対象だった音だけを、次音とコード終端までの余裕に収まる量へ抑える（1/16拍刻み、最大0.25拍）。次の強拍を後ろへ動かさず、危険だった弱い入口だけを調整する。境界を越えない。
2. 音高選択は元の変奏計画の拍位置を使う。安全化の拍調整を理由に、音高列まで変えない。旧324候補の音高列SHA-256を固定して比較。
3. 変奏の最小音価を0.01→0.1拍へ。修復対象37音以外の音の開始/長さはすべて不変だった。0.1への一律な水増しだけで重なりを残す方法ではなく、入口の安全な移動量を先に確保している。
4. 完全同時の新規主旋律は、和声音（分数コードの指定低音を含む）→Pitch Lock→Velocityの順で1音にまとめる。変奏の土台はコピーして処理し、採用済みの土台には書き戻さない。指定フィクスチャでは重複0件のため、統合による減数も0。
5. 予防として、新規主旋律のPerformanceSpecにだけminimumNoteBeats=0.1を指定し、Gateで最小音価を割らない。既存/未指定のPerformance仕様・他パート・MIDI変換器は変更しない。

最初に「危険な移動を全部取りやめる」案も測ったが、候補一致率0.703756となり上限0.70を超えたため不採用。最終案は安全な範囲の移動を残し、基準を緩めず0.686284を満たした。
