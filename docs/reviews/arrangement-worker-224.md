# 全曲生成を画面から分離（Issue #224・3番）

方向選択/強さの再生成、相談案の音の準備、履歴からの版復元をmodule Workerへ移す。既存の同期APIとエンジンは互換性・比較用に残すが、これらの画面入口は非同期経路を使う。進行中の計算はterminateで中止できる。曲のオブジェクトが変わった場合は結果を適用せず、履歴へも生成結果を追加しない。新しい生成を始めた場合も古い計算を中止する。

方向生成と版復元の適用処理は同期APIと共有。相談案は曲オブジェクトごとにキャッシュし、準備が終わるまで適用/変更後試聴を無効化する。準備中/失敗/中止/再試行を表示。保存形式・生成の採否/順序/品質閾値は変えない。

リフ診断はWorker応答の別フィールドで運び、main側のWeakMapへだけ戻す。生成結果のJSONや保存データには診断を追加しない。

新規6テスト：Workerの結果/診断輸送と非永続、キャンセル/開始前キャンセル、Worker/通信失敗、途中編集の結果破棄、キャンセルで音符を適用しない、同期/非同期で同じ入力と採用結果。既存の方向/版のテストを合わせ26件成功、build成功。実Workerでの固定seed全結果一致と実ブラウザ操作性は4番のE2Eで検証する。

## マージ前自動レビューへの対応

相談案を受け取る最初のproposalsFromResponseもWorkerへ移した。初回計算が作った全曲案を応答で返し、返事をprojectへ公開する前に同じprojectキーへキャッシュするため、画面の準備effectで再生成しない。キャンセル/途中編集で返事を反映しない。AI利用量は応答取得時に記録し、準備を中止しても消費を隠さない。

適用済みのカードは、音のキャッシュがなくても保存済みpointsを表示する。準備待ちの説明は未適用カードだけへ限定。新規3テスト（初回の3案の保持/公開前キャッシュ、適用済み説明の保持、未適用の準備案内）と既存関連を合わせ9件成功。
