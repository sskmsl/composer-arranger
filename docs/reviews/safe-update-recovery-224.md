# 安全な更新と画面読込の復旧（Issue #224・2番）

更新通知の再読み込みはflushSaveを待ち、失敗なら画面を保持して中止理由を伝える。同じ保存バリアを遅延読込/描画失敗のErrorBoundaryでも使う。画面データを消す自動reloadは行わず、JSON退避と明示的な保存後reloadを提供する。

画面を前面に開いたままでも更新を検知するよう、既存の表示切替に加えて60秒間隔/focusで確認。非表示中は通信しない。新しい画面や保存形式・音楽判定は追加しない。

保存完了前にはreloadしない/失敗・例外ではreloadしない新規2テスト。遅延JSを遮断する実ブラウザ検証は後続の4番で追加する。
