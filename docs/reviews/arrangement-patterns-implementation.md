# アレンジの「展開の型」の追加(イントロ、途中の抜き、フェードアウト)

> **後続の改修(`arrangement-emotion-mechanisms.md`)**: この文書の3つの型は、「感情を動かす仕組み」の下の手段へ再編した
> (ドラムレス=期待→到来、低域とキックを抜く区間=引き算による対比、フェードアウト=終止の減衰)。参照を5本に増やして実測した結果、
> ドラムレスは5本中1本でしか観察されず、リズムを進めたまま低域だけ保留する形(5本中3本)を手段に加えた。
> 終止の減衰は、アウトロで終わる曲では既定で働くようになった(`emotionalAuto: false` で従来の出力)。
> 下の「型を選ばない出力は従来と同じ」は、この既定を除く。


目的は、アレンジのパターンを増やすこと。参照した録音(個人の制作物、匿名)の型を、3つの「展開の型」として追加した。
どれも、生成条件の意図(`directive.intention`)に決まった文があるときだけ働く。指示を出さない限り、出力は従来と同じ。
方向選び(DirectionPicker)に、型を選ぶ入口を足した。新しい画面・保存フィールドは無い。

## 参照録音の観察(信号処理による推定。聴感の評価ではない)

録音は約4分35秒、テンポは約117.5 BPM(8小節がちょうど16.4秒)。楽器の判別と正確なコード推定はできない。

| 観察 | 確度 | 型 |
| --- | --- | --- |
| 冒頭の8小節は、キックがほぼ無く、低域が弱く、中域と高域の質感が中心 | 中〜高 | 1 |
| 9小節目の頭で、全体が約+6dB、低域が+6dB、キックが入る(1小節あたり約30発音) | 高 | 1 |
| 途中に、低域とキックを約7小節抜く区間があり、戻すときに大きく入る | 中〜高 | 2 |
| 終わりは最後の約3小節で、-3.5dB → -11dB → -24dB のフェードアウト | 高 | 3 |
| 左右の広がりは、イントロでは大きく、ドロップ後は狭まる | 中 | 未実装 |

## 3つの型(文言は `src/core/arrangementPatterns.ts` に1か所だけ置く)

| 型 | 意図の文 | 働き |
| --- | --- | --- |
| 1 ドラムレスのイントロ→頭で一斉に入る | ドラムレスで広がるイントロから、頭でキックと低域が一斉に入る | イントロ(4小節以上)でキック・スネア系・clap・主/補助ベース・コントラバスを保留。Pad と Pad Air は通して鳴らす。次の区間(ブレイクダウン・アウトロは除く)の頭で一斉に入れる |
| 2 低域とキックを抜く区間→戻りで大きく | 低域とキックを抜いた区間を作り、戻りで一斉に大きく入れる | 最初のブレイクダウン(無ければ最初のブリッジ、4小節以上、直後がアウトロでない)でキック系と低域を保留。次の区間の頭で一斉に戻し、入口にクラッシュとシンバルのスウェル、直前にフィルを置く。曲に1か所 |
| 3 フェードアウトで終える | 終わりはフェードアウトで終える | 最後の区間の最後の4小節で、小節ごとに velocity の上限を -3 / -8.5 / -16 / -24dB へ下げる。長く鳴り続ける音は、小節の境目で切って弱く鳴らし直す |

共通の扱い:
- 境界の分散処理(`scheduleBoundaryRoles`)と見直し(`refineBoundaryRoleSchedule`)は、一斉に入る層の入場を遅らせない
  (どちらも「1小節に交代2層まで」の上限のために入場を散らすので、そのままだと一斉の入場が崩れる)。
- `directive.preserve` / `add` の層、`directive.sectionId` で別の区間に絞った指示には触れない。
- 区間の `intention` の文言に、働きを一文ずつ追記する(既存の長区間の追記と同じ形式)。
- 低域を控えるヴァースの指示(`asksLowEndHoldBack`)とは言い回しを分け、お互いを巻き込まない。
- フェードの上限は、小節の境目の分割と velocity の上限だけなので、仕上げ処理を何度通しても結果が変わらない。

## 画面

方向選びの下に「展開の型」(任意・複数選択)を追加。選んだ型の文言だけが、方向の意図に続いて生成へ渡る。
型の文言は brief(相談文)には入れない。brief は音の指示として別に解釈され(`arrangementSoundInstructionFromText`)、
「ドラム」「イントロ」の語で全曲の入退場の計画が止まるため。選ばなければ従来と同じ。

## 実測(書き出したMIDIを再読込して測る。seed 1〜6)

Cm、4/4。

| 型 | 測定 | 結果 |
| --- | --- | --- |
| 1 | イントロ4・8・16小節で、キック・スネア系・clap・ベース類がイントロで鳴る | 0(全seed)。指示なしでは、8小節のイントロの主ベースは5小節目から鳴る |
| 1 | 次の区間の1小節目で同時に鳴る保留対象の層 | 3層以上(キック・主ベース・補助ベースなど) |
| 2 | 抜く区間で、キック系・低域の層が鳴る | 0(全seed、ブレイクダウン・ブリッジの両方) |
| 2 | 戻りの1小節目の、キックと主ベース | 頭から鳴る(全seed)。戻りが通常のヴァースでも、頭にクラッシュが入る(指示なしでは入らない) |
| 2 | 抜く区間の無い曲 | 出力が変わらない |
| 3 | 最後の4小節の、鳴っている音の velocity の平均 | 小節ごとに下がり、最後の小節は最初の小節の0.45倍以下。フェードより前は変わらない |
| 3 | 仕上げ処理をもう一度通す | 同じ結果(上限が重ならない) |
| 1+2+3 | 方向選びと同じ経路で3つを同時に選ぶ | 3つとも働く。brief は音の指示として読まれない |

- 指示なし、および無関係な指示(低域を控えるヴァース)の出力は、変更前の main と24パターンで一致した
  (イントロ8・16小節を含む2構成 × seed 6 × 指示 2 種)。
- 新しいテストは、型1では変更前の生成コードで4件が失敗する。

  作業前は 1382件。既存テストの期待値は変更していない。

  並列で重なった実行では、まれに5秒を超えて落ちる。変更前から起こる負荷由来の不安定さで、再実行で成功する。

## レビュー指摘への対応(PR #197、Codex の3件。いずれも再現するテストを先に書いて失敗を確認)

- 「低域とキックを抜く区間」の文が、既存の「低域を控える」の判定にも当たり、ヴァース/Bメロの補助ベースまで消えていた
  (「抜く区間」の表記）。低域保留の判定は、この文を除いて行うようにした。
- 長いイントロ（例: 20小節）で、派生層の Pad Air がイントロの途中から入っていた。長いヴァース（16小節）の頭に戻す層も、
  派生層（Sub Bass など）が対象から漏れていた。派生層は元の層（Dark Pad、Bass）が鳴る区間かで判定するようにした。
- フェードアウトが、保持を指定した層（とその派生層）の音まで書き換えていた。他の処理と同じく、保持指定は書き換えない。

## 未実装・限界

- 左右の広がり(イントロは広く、ドロップ後は狭く): 区間ごとの広がりを持つ計画の項目が無いので、実装していない。
- 高域の質感の増加は、既に鳴る層(Pad Air、High Glass)の範囲のみ。層は足さない。
- フェードアウトは velocity による段階的な下げ。長い音は小節ごとに鳴らし直すので、滑らかなミックスのフェードではない。
  Logic Pro 側でトラックのオートメーションに置き換えるほうが、より自然になる。
- 8小節ごとの層の入退場を曲全体に当てはめる型は、確度が低い部分(メロディの入場位置など)まで固定してしまうため入れていない。
- 録音の観察は信号処理による推定で、聴感の一致は保証しない。
