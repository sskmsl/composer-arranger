# アレンジの質を主旋律と同じ水準へ上げるための相談(Codex への依頼書)

主旋律の生成は、実在の楽譜で較正した物差しによる候補の選抜、推敲、和声の整合、段階の記録まで整ってきた。作曲者から、アレンジ(イントロ・短いフレーズ・対旋律・装飾)も同じ水準にしてほしいという依頼があった。

現状の仕組みと測定結果、制約、Claude 側の施策案をまとめる。Codex には次をお願いしたい。

- Claude 案への反論と、見落としの指摘
- Claude 案にない、独立した施策案

条件の補足:

- イントロは主旋律を参照して作る。単独で鳴らす使い方と、主旋律と同じセクションで重ねる使い方の両方で数えた
- 装飾は、何も採用していない条件と、短いフレーズ・イントロ・対旋律の1案目を採用した条件(アプリの採用後の経路)の両方で数えた
- 「(線)」の列は、同じ開始の音を最高音1つにした線の音数を分母にした

列の定義:

- 「主旋律と半音でぶつかる割合」: 主旋律と0.5拍以上重なる音のうち、短2度・長7度(オクターブ違いを含む)の音程になる割合
- 「主旋律との平行5度・8度」: パートの隣り合う2音の間で主旋律も音が替わり、両方が同じ向きに動いたときに、完全5度・8度(同度)が続いた割合

8音以上の線の古典らしさ(主旋律の物差し)は、イントロ・短いフレーズ・対旋律で 10〜25 だった(主旋律は 94〜100)。ただし物差しは8小節前後の歌の旋律で較正したもので、短い器楽の素材にはそのまま当てはまらない。比較には使わない。

読み取り(Claude):

- 対旋律は、主旋律との関係(半音の重なり・平行)がきれい。ただし音が少なく(1案に約5音)、線としての動きの質は測れていない
- 装飾と短いフレーズは、主旋律との平行5度・8度が 4〜24% ある。半音の重なりも 3〜9% ある
- イントロは、1音だけ飛び出す音が主旋律の約3〜6倍、調の外の音も約3倍ある。短い器楽の素材で、跳ねる音型が意図されている可能性がある。主旋律と重ねると、平行5度・8度が 9〜12% ある
- 装飾は、採用済みのレイヤーがあると平行・半音の重なりが少し減るが、他のレイヤーとの半音の重なりが 8〜10% ある
- 短いフレーズの Aメロは、77% の音が主旋律より上にある。`short-material-identity-audit.md` の「混んだ主旋律から音域を離す」の結果と見られる

## 4. 制約(主旋律と同じ)

- 既存の曲の旋律・音型を保存・再現しない。較正に使うのは、パブリックドメイン・CC0 など権利が明確なデータの統計だけ。
- 閾値や下限を、テストを通すために下げない。
- 新しい物差しは、選抜に使う前に、開発に使っていない条件で確かめる。
- 作曲者の試聴は、方向を変える判断に限り、1回3組まで。
- ブラウザで動く TypeScript。生成は数秒以内。
- 結果を見て直した条件は開発用として扱い、確認には別の固定条件を使う。

## 5. Claude の施策案(優先順)

1. **主旋律との対位の基本を、全パートで同じ物差しにする**: 平行5度・8度(と直行の5度・8度)、半音の重なり、声部の交差を、1つの共通関数で測る。装飾・短いフレーズの選抜で、対旋律と同じように減点または除外する。対旋律では、すでにほぼ0になっている。
2. **パートごとの固定条件の前後比較テスト**: 上の表を記録専用テストとして残し、開発用と確認用の条件を分ける。施策ごとに、同じ表で前後を示す。
3. **段階の記録を4パートに広げる**: 主旋律と同じ `stageTrace` で、どの段階で平行・衝突・飛び出す音ができたかを追えるようにする。
4. **実在の楽譜で較正した「内声・対旋律らしさ」**: 権利が明確なコーパス(music21 同梱のバッハのコラール、OpenScore Lieder のピアノ右手など)から、主旋律に対する副次的な線の統計(反進行・斜進行の割合、協和音程の割合、動きの補い合い)を取る。これを、対旋律・短いフレーズの選抜の物差しにする。
5. **選んだ後の推敲(4半音の上限つき)をアレンジにも**: 平行・半音の重なりだけを直す局所的な推敲。主旋律の推敲と同じく、形とリズムを保つ範囲に限る。
6. **イントロの跳ねる音型の扱い**: 1音だけ飛び出す音・調の外の音が多いのが意図か欠陥かは、数では決められない。作曲者が気になると言うまでは、記録だけにする。

## 6. Codex にお願いしたいこと

1. 上の案への反論と、見落とし。特に「主旋律用の物差しを、器楽の短い素材に当ててよいか」。

3. 優先順位と、それぞれの効果を前後比較でどう測るか(開発用と確認用の条件の分け方を含む)。
4. 実装の危険(生成時間、既存テストの閾値、各パートの既存の設計との衝突)。
