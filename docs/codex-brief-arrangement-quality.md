# アレンジの質を主旋律と同じ水準へ上げるための相談(Codex への依頼書)

主旋律の生成は、実在の楽譜で較正した物差しによる候補の選抜、推敲、和声の整合、段階の記録まで整ってきた。作曲者から、アレンジ(イントロ・短いフレーズ・対旋律・装飾)も同じ水準にしてほしいという依頼があった。

現状の仕組みと測定結果、制約、Claude 側の施策案をまとめる。Codex には次をお願いしたい。

- Claude 案への反論と、見落としの指摘
- Claude 案にない、独立した施策案

列の定義:

- 「(線)」: 同じ開始の音を最高音1つにした線で数え、分母もその線の音数。和音の素材を1本の線として見る代理で、モチーフの核や持続する内声そのものではない
- 主旋律と重なる音: 主旋律と0.5拍以上重なる音の数。短2度・長7度は、その重なりのうち実際の音域の間隔が1半音・11半音のもの(複音程は別に記録)
- 同じ向きの組: パートの隣り合う2音の間で主旋律も別の音へ替わり、両方が同じ向きに動いた組(平行の判定対象)
- 平行5度・8度: その組のうち、絶対音程で同じ種類の完全音程(5度→5度、8度→8度)が続いたもの。4度は含めない
- 主旋律より上: 主旋律と同時に鳴っていて比べられた線の音のうち、上にある割合
- 上下の交差: 比べられた音が続く所で、主旋律との上下が入れ替わった回数
- 鳴っていない拍の割合: そのパートと主旋律(組み合わせ条件では採用済みのレイヤーも)のどれも鳴っていない拍の割合

生成を見送った(候補が返らなかった)回数は、12回中、対旋律 Aメロ 1、装飾 Aメロ(単独・組み合わせ)各1。

読み取り(Claude、開発用の条件):

- 主旋律との短2度の重なりは、どのパートもほぼ 0。以前の集計の「半音でぶつかる」は、音程のクラスだけで見ていたので、離れた長7度・複音程を含んでいた
- 平行5度・8度は、判定対象の数そのものが少ない。装飾は同じ向きの組が 100案あたり十数組で、平行は 0〜1。対旋律は 0(判定対象も 0〜3)
- 短いフレーズ(平行 6〜9、率 0.11〜0.13)と、主旋律と重ねるイントロ(平行 7〜10、率 0.08)は、平行が残る
- イントロは、主旋律と重ねると上下の交差が 1案あたり約1〜2回ある
- 短いフレーズの Aメロは、比べられた音の 96% が主旋律より上にある(`short-material-identity-audit.md` の音域の分離の結果と見られる)
- 装飾を採用済みのレイヤーと組み合わせると、鳴っていない拍の割合が 0.33〜0.36 から 0.17 に下がる。レイヤーを重ねるほど余白が埋まる

## 4. 制約(主旋律と同じ)

- 既存の曲の旋律・音型を保存・再現しない。較正に使うのは、パブリックドメイン・CC0 など権利が明確なデータの統計だけ。
- 閾値や下限を、テストを通すために下げない。
- 新しい物差しは、選抜に使う前に、開発に使っていない条件で確かめる。
- 作曲者の試聴は、方向を変える判断に限り、1回3組まで。
- ブラウザで動く TypeScript。生成は数秒以内。
- 結果を見て直した条件は開発用として扱い、確認には別の固定条件を使う。

## 5. Claude の施策案(優先順)

1. **主旋律との対位の基本を、全パートで同じ物差しにする**: 平行5度・8度(と直行の5度・8度)、半音の重なり、声部の交差を、1つの共通関数で測る。装飾・短いフレーズ・イントロ(主旋律と重ねるとき)の選抜で、対旋律と同じように減点または除外する。装飾は、採用済みの他のレイヤーとの関係も同じ物差しで見る。対旋律では、すでにほぼ0になっている。
2. **パートごとの固定条件の前後比較テスト**: 上の表を記録専用テストとして残し、開発用と確認用の条件を分ける。施策ごとに、同じ表で前後を示す。
3. **段階の記録を4パートに広げる**: 主旋律と同じ `stageTrace` で、どの段階で平行・衝突・飛び出す音ができたかを追えるようにする。
4. **実在の楽譜で較正した「内声・対旋律らしさ」**: 権利が明確なコーパス(music21 同梱のバッハのコラール、OpenScore Lieder のピアノ右手など)から、主旋律に対する副次的な線の統計(反進行・斜進行の割合、協和音程の割合、動きの補い合い)を取る。これを、対旋律・短いフレーズの選抜の物差しにする。
5. **選んだ後の推敲(4半音の上限つき)をアレンジにも**: 平行・半音の重なりだけを直す局所的な推敲。主旋律の推敲と同じく、形とリズムを保つ範囲に限る。
6. **イントロの跳ねる音型の扱い**: 1音だけ飛び出す音・調の外の音が多いのが意図か欠陥かは、数では決められない。作曲者が気になると言うまでは、記録だけにする。

## 7. Codex の返答と、合意した進め方(PR #184)

Codex(Sol)の返答の要点:

- 共通にするのは観測までにする。選抜の重みと除外条件は役割ごとに決める。独立した対旋律、主旋律を補強する重複、単独のイントロ、和音化したモチーフでは目的が違う。平行5度・8度を一律に禁止したり、主旋律より上を声部交差として禁止したりすると、補強や既存の音域の分離まで壊す
- 第一の施策は、音高の修正より「配置・役割の競合を減らす」こと。既存の `assessReactiveNegativeSpaceFit`・`assessReactiveRoleComplementarity`・主旋律の `protectedMoments`・`assessDecorationNeed` を再利用する。そのうえで、同じ応答の位置を複数のレイヤーが取り合う・主旋律の頂点へ一斉に入る・休みを全部埋める、といった場合を観測する。不要な音を削る案・生成を見送る案・既存のモチーフを短く再提示する案・現状を比べる。音数を増やすこと自体は目的にしない
- 確認は、先に固定した確認用の条件で、現状と施策1つを比べる。率だけでなく、判定対象の数・重なりの拍数・音数・残る余白・候補の不足と見送りの数を残し、単に黙らせて率を下げたのか区別する。数値や理論上の点数の改善は聴いた品質の証明にしない。方向の判断が必要なときだけ、同じ音色・音量で最大3組の盲検比較にする
- 実在の楽譜での較正と、4半音の推敲は後回し。歌の主旋律で較正した物差しを短い器楽の素材に使わない。イントロの飛び出す音・調の外の音は、数だけで欠陥と扱わない
- 実装の注意: 既存の品質の下限を下げない。音域の分離・Creative Risk・和声の補正と競合させない。評価は最終的に返す音にかける(旧来の独立した装飾の `buildCandidate` は、返す音が和声の補正後なのに、いくつかの評価が補正前の音を見ている)。装飾の語彙はイントロ(Signature)にも統合されているので、旧来の独立した経路だけの改善を全体の改善と扱わない。候補を増やす前に、既存の解析を1入力につき再利用し、生成時間も測る

この PR では、観測と測り方の修正までを入れる。施策は次の PR から1つずつ入れる。
