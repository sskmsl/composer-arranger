# Codex desktop への確認依頼:実験2(一時ファイル)

このフォルダは確認用の一時ファイルです。Codex desktop の判断が記録され、答えを開いたら、このフォルダだけを削除してからマージします。

## これは何か

- `docs/rhythm-memory-controls.md` の実験2です。未使用の12の和声構造(seed 7001〜7012)で、サビの2案を比べます。
- 人が覚えやすいことを示す試験ではありません。未使用の条件での、探索的な構造の比較です(#176 での合意)。

## ここにあるもの

- `pairs.md` / `pairs.json`:各組の調、コード(1小節ずつ)、テンポ、A / B の音(音名・拍・長さ)。
  - A / B のそれぞれについて、生成時点の核、冒頭2小節、8小節全体を分けて載せています。
- `midi/`:1〜8小節が A、10〜17小節が B(9小節目は休み)。旋律とコードの2トラックで、テンポは 90。

## ここにないもの

- 方式名、指標の値、答え(A / B がどちらの方式か)は、このリポジトリに入れていません。
- 答えは SHA-256 で固定しています(`docs/rhythm-memory-controls.md` の「実験2の実行記録」)。判断の記録後に、答えの JSON をそのままのバイト列でこの PR に載せます。ハッシュが一致すれば、判断の後で答えを変えていないと確かめられます。

## お願いしたいこと

1. 各組で、一度聴いて覚えやすく、歌い返しやすいサビの構造はどちらかを、A / B / 同程度から選んでください。理由は1〜2行でお願いします。
   - 核だけ・冒頭2小節・8小節全体で判断が分かれる組は、それも書いてください。
2. 判断は、答えを開く前にこの PR のコメントとして記録してください。
3. 生成器を動かして答えを割り出すことはしないでください(生成に使ったコミットは記録してあります)。
4. 判断の記録後に、答え、指標(シンコペーション、拍を作る強さ、輪郭の一致)、基準値を別のコメントで出します。一致の数は、同程度の扱いを分けて報告します。
