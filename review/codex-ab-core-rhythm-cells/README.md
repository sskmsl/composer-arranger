# Codex への確認依頼:サビの「素直な型」の核(一時ファイル)

このフォルダは確認用の一時ファイルです。Codex の確認が済んだら、このフォルダだけを削除してから、この PR のコード変更をマージします。

## 経緯

- #173 のブラインド比較(V0 と V2)は、作曲者 4対4、Codex 5対3 で、好みは曲によって分かれた。
- 作曲者の判断で、**サビの3案に、従来の核(varied)と素直な核(plain)の両方を入れる**ことにした(この PR のコード変更)。
- plain の核は、Codex の提案(#173)どおり、種類数ではなく短いリズムの単位のくり返しで選ぶ。
  - `rhythmicHookQuality` は `src/melody-engine/hookFirst.ts` にある。
  - 評価の内訳は、くり返し 0.45、まとまり 0.15、拍への錨 0.2、弱起の解決 0.1、骨組みだけでない 0.1。
  - 長さが1種類だけの核は、単位のくり返しとは数えない。
  - #173 の8組では、Codex が選んだ側を8組すべてで高くする。お手本のテストは `hookFirst.test.ts` にある。ただし、この8組を見て作った物差しなので、今回の別の8組で確かめたい。
- 影響範囲は plain の1案だけに絞った。
  - 従来の `hookability`、varied の選び方、Aメロは変えていない。
  - 当初は `hookability` 自体を置き換えたが、尺度が変わって比較テストの下限(0.87)に届かず(0.758)、Aメロの選び方も変わって別の回帰テストが4件落ちた。聴いて確かめる前の段階としては変化が大きすぎるので、この形にした。
  - 比較テストの下限は数字を変えずに通っている(8小節 0.872)。

## ファイル

- `pairs.md` / `pairs.json`:各組のコード、A / B の全ての音(音名・小節内の拍・長さ)、指標。
- `midi/`:作曲者に渡した MIDI(前半 1〜8小節が A、10〜17小節が B)。
- `ANSWER_KEY.md`:A / B がどちらの型か。**先に手順 1 を済ませてから開いてください。**

## Codex にお願いしたいこと

1. **ブラインドでの判断**(`ANSWER_KEY.md` を開く前に)
   - 各組について A / B / 同程度を選び、1〜2行の理由を書いてください(前回と同じ観点)。
2. **答えを見たうえでの評価**
   - `rhythmicHookQuality` が、前回の8組に合わせすぎていないか。
   - plain を1案に入れる今の形でよいか。
   - `rhythmicHookQuality` を将来 `hookability` 全体へ広げるときに必要な準備(尺度の正規化、下限の扱い)。
3. この PR のコード変更(`hookFirst.ts`、`generateFromChords.ts`、`candidateSelection.ts`)のレビュー。
4. 返答は、この PR へのコメントでお願いします。
